# 産業保健ビジネス調査プロジェクト — 設計仕様書

## Context

産業医である先生が、日本の産業保健分野における需給ミスマッチを発見し、ビジネスチャンスとして開発したいと考えている。特に「健診結果の判定・事後措置」と「休復職支援・メンタルヘルス」の2領域に課題感があるが、ターゲットユーザーやビジネスモデルはまだ未定。まず市場調査から始め、データに基づいて判断する「リサーチファースト」アプローチを採用する。

## プロジェクト全体構成

| フェーズ | 内容 | 成果物 |
|---------|------|--------|
| Phase 1 | 市場調査 | 競合マップ・サービス一覧レポート |
| Phase 2 | ギャップ分析 | 需給ミスマッチ分析レポート |
| Phase 3 | テーマ・ターゲット選定 | ビジネスコンセプトシート |
| Phase 4 | MVP設計・開発 | 動くプロトタイプ |

## Phase 1: 市場調査（今回の実装スコープ）

### 調査対象カテゴリ

1. **健診結果管理・就業判定支援サービス**
   - 健診データの取り込み・管理
   - 就業区分の判定支援
   - 受診勧奨・事後措置の管理
   - 特殊健診対応

2. **休復職支援・メンタルヘルス管理サービス**
   - 休職者の状態管理・フォローアップ
   - 復職プログラム管理
   - ストレスチェック関連
   - EAP（従業員支援プログラム）

3. **産業保健全般のSaaS/プラットフォーム**
   - 産業医業務を包括的に支援するサービス
   - 衛生委員会支援、職場巡視記録など
   - 産業医マッチングサービス

### 各サービスの調査項目

- サービス名・提供企業・URL
- 主な機能一覧
- ターゲット（企業規模・業種・利用者）
- 価格帯・課金モデル
- 強み・差別化ポイント
- 弱み・未対応領域（分かる範囲）

### 調査手法・使用ツール

| ツール | 用途 |
|--------|------|
| **WebSearch** | 競合サービスの検索、市場レポートの発見 |
| **WebFetch** | 個別サービスサイトの詳細情報取得 |
| **GitHub MCP** | 産業保健関連OSSの調査 |
| **MCP Registry** | 関連MCPサーバーの有無確認 |
| **Claude Preview / Playwright** | サービスサイトの詳細調査（必要に応じて） |

### 調査の進め方

1. **網羅的検索**: カテゴリごとにWeb検索で既存サービスを収集
2. **詳細調査**: 各サービスのWebサイトから調査項目を埋める
3. **OSS調査**: GitHub上の関連プロジェクトを検索
4. **整理・レポート作成**: 収集データをMarkdownレポートに構造化

## Phase 2以降（概要のみ）

### Phase 2: ギャップ分析
- Phase 1の調査結果と先生の現場知識を突き合わせる
- 「既存サービスでカバーされていないが、実務上必要なもの」を特定
- 需要の大きさと参入障壁を評価

### Phase 3: テーマ・ターゲット選定
- ギャップ分析の結果から最有望テーマを選定
- ターゲットユーザーのペルソナ定義
- ビジネスモデル（SaaS、コンサル、受託等）の検討
- 簡易な事業計画

### Phase 4: MVP設計・開発
- 選定テーマでMVPを設計
- Claude Codeで開発
- ユーザーテスト

## 検証方法

- Phase 1完了後、先生にレポートを確認いただき、現場感覚とのズレがないかレビュー
- 競合サービスの情報が正確か、実際にサービスサイトにアクセスして確認
- 空白地帯の仮説が妥当か、先生の実体験と照らし合わせて議論
